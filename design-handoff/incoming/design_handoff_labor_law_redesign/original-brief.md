## 1. 這是什麼專案

**勞基法查詢小幫手**：協助台灣勞工判斷自己的出勤是否違反勞基法、估算可能少領的加班費／假日工資，並用「律師口吻」回答勞工用口語描述的職場問題（例如「老闆叫我連上 7 天班合法嗎」「被排擠算職場霸凌嗎」）。

- **目標使用者**：一般勞工，不熟悉法律條文、可能對法律用語感到有距離感，甚至在勞資爭議中處於焦慮或委屈的情緒狀態。**不是** HR、不是法務、不是給專業人士看的工具。
- **語氣定位**：像一位親切但專業的律師朋友——會講白話文解釋法條，會明確告訴你「老闆哪裡可能違法」「你可以主張什麼」，但不會用生硬的法律術語轟炸使用者。
- **這不是**期貨、股票、金融資料類產品，沒有相關邏輯，設計上也不需要往金融交易平台的視覺語言靠。

## 2. 這次任務範圍

**只做視覺 / 美學的重新設計，不動功能邏輯、資料流、表單欄位、判斷結果內容。**

- 保留所有現有的資訊架構、頁面流程、文案內容
- 保留所有元件的 props/state 介面（實作端會按你的設計重新套版，但元件對外行為不能變）
- 技術限制：
  - **Next.js 14 App Router + Tailwind CSS**（含 `@tailwindcss/typography` plugin，因為 AI 回答用 `react-markdown` + `prose` class 渲染）
  - 目前**沒有使用 `next/font`**，`body` 的 `font-family` 就是系統預設 `Arial, Helvetica, sans-serif`（見第 5 節）—— 如果你建議換字體，請確保是可以透過 `next/font/google` 或自架字體檔案接的字體，中文字重要（繁體中文顯示要漂亮）
  - 響應式：桌面版有上方導覽列，手機版是底部 4 個分頁的 tab bar（見截圖與第 4 節）

## 3. 這次選定的設計方向（已與專案負責人確認，請照此執行）

| 決策項目 | 選擇 | 補充說明 |
|---|---|---|
| **整體氛圍** | 親切溫暖小幫手感（優化現況，不是砍掉重練） | 現況已經是「柔和卡片 + 友善語氣」路線，方向是對的，但質感偏業餘，這次是把同一個路線做得更精緻、更有質感，**不是**轉型成冷硬的企業風 |
| **圖示系統** | 混合式 | Hero 區塊、CTA 按鈕、警語橫幅等「傳達溫度/情緒」的地方**保留 emoji**（⚖️💰✅💬⚠️等）；導覽列、系統性 UI 元件（卡片標籤、狀態標示、資料視覺化）**改用正式 icon 圖示庫**（建議 [Lucide](https://lucide.dev/) icons，因為是 tree-shakable 的 React component，與 Tailwind 生態相容度高，方便前端工程師直接 `import { Icon } from "lucide-react"` 替換） |
| **主色調** | 深藍 + 金色 | ⚠️ 重要限制：因為整體氛圍要「親切溫暖」，**配色不能做成死板冰冷的企業法律事務所官網**。深藍建議用偏柔和、飽和度較低或偏靛藍的深藍（而不是純黑藍），金色只作為強調色/點綴（CTA、重點數字、圖示），不要大面積鋪金色。目標是「值得信賴但不會讓委屈的勞工覺得被拒於門外」的感覺 |

## 4. 網站地圖與各頁面用途

共 5 個路由，全部走同一個 `AppShell`（見第 5 節導覽列說明）：

### `/`（首頁）
- Hero 區塊：深色漸層背景（現況 `teal-700 → teal-900`）+ 標題「老闆有沒有少給你錢或假？」+ 兩個 CTA 按鈕（「算算我少拿多少」導向 `/check`、「問 AI 律師」導向 `/ask`）
- 兩張「進入方式」卡片：快速出勤判斷 vs 情境式詢問
- 常見問題快捷連結列表（4 個，點了直接帶問題進 `/ask`）
- 服務保證區塊：3 個小圖示卡（不儲存個人資料／即時分析／依據現行法條）
- 底部固定放 `DisclaimerBanner`（見第 5 節）

### `/check`（快速判斷 — 3 步驟精靈表單）
- 步驟指示條：① 雇用類型 → ② 出勤紀錄 → ③ 確認送出（見截圖 01）
- 步驟一：雇用類型單選卡（月薪制／時薪制／派遣勞工），選到時薪制會展開一個「時薪資訊」黃底提示區塊，讓使用者填平日/假日時薪（選填）
- 步驟二：日曆式出勤紀錄輸入（本文件未附截圖，但邏輯是逐日勾選出勤/例假/休息日）
- 步驟三：確認送出

### `/check/result`（判斷結果頁）
- 頂部大紅色橫幅：「你這段期間可能少領 NT$ X,XXX」+ 一句依據法條的說明（見截圖 02）
- 風險摘要卡：`RiskBadge`（高/中/低風險）+ 一句話總結 + 4 個統計數字方塊（總工時／加班時數／最長連班／日均工時）
- 「詳細分析」逐條卡片列表：每條規則一張卡，左側用顏色色條（綠=合規／紅=疑似違規）區分，內容包含規則說明、可信度標籤、相關法條連結、若有金額則顯示試算明細（見截圖 03）
- 頁面下方會有 AI 律師分析的 CTA（開源版走 `OpenSourceAiButtons`，見第 5 節）

### `/ask`（情境詢問 — AI 聊天）
- 聊天氣泡介面：使用者訊息靠右（深色底），AI 回答靠左（白底卡片，裡面是 Markdown 渲染的律師口吻長文分析）
- 上方有 6 個「範例問題」快捷按鈕（連上 7 天班、加班費怎麼算、職場霸凌等）
- AI 回答下方會附「相關法條」連結列表
- 開源版（`NEXT_PUBLIC_MODE=opensource`）不會直接呼叫後端 LLM，而是顯示 `OpenSourceAiButtons`：一個引導使用者「複製提示詞 → 開 ChatGPT/Gemini → 貼上」的三步驟卡片（見第 5 節，這是本站雙模式架構的核心 UI，設計上要清楚呈現「不會把你的資料傳給 ChatGPT/Gemini」的信任聲明）

### `/law`（法條查詢）
- 一個搜尋框 + 6 個主題快捷標籤（全部／工時／加班費／休假／資遣／工資）
- 搜尋結果列表：每筆結果有一個文件類型色標（法條/施行細則/函釋/判決/仲裁，各自不同顏色）+ 標題 + 條文內容摘要

## 5. 現有視覺系統（現況的「骨架」要保留，但美學要重做）

### 色彩（Tailwind 預設色，未做任何客製化）
- 主色：`teal-700`（導覽列、主要按鈕、Hero 漸層起點）／`teal-900`（Hero 漸層終點、選中狀態）
- 風險/狀態色：`red`（高風險、少領金額橫幅）／`amber`（中風險、警語橫幅）／`green`（低風險、合規）
- 背景：`gray-50`（全站底色）
- 卡片：`bg-white` + `border-gray-200` + `shadow-sm`，圓角大量用 `rounded-xl` / `rounded-2xl`
- 開源版 AI 引導卡片是唯一用到 `indigo/purple` 漸層的地方（`OpenSourceAiButtons`）

### 字體
- **完全沒有自訂字體**：`body { font-family: Arial, Helvetica, sans-serif; }`，這是現況美學最大的弱點之一，繁體中文用 Arial 顯示無法呈現排版質感

### 版面
- 全站容器：`max-w-5xl mx-auto`
- 桌面：上方橫向導覽列（深色背景 `teal-700`），4 個分頁（首頁/快速判斷/情境詢問/法條查詢）
- 手機：頂部只顯示品牌名（`⚖️ 勞基法小幫手`），底部固定 4 個分頁的 tab bar，選中項目變 `teal-700` 文字

### 現有共用元件清單（實作端會依你的設計逐一重做樣式）
| 元件 | 用途 | 現況樣式重點 |
|---|---|---|
| `AppShell` | 全站導覽外殼 | 見上方版面說明 |
| `RiskBadge` | 高/中/低風險標籤 | 圓角膠囊，紅/琥珀/綠三色 |
| `DisclaimerBanner` | 法遵警語（「本系統提供參考資訊，不構成法律意見…」） | 琥珀色底橫幅，**內容不可刪減**（法遵要求） |
| `ChatThread` | 聊天氣泡 | 使用者訊息深色靠右、AI 回答白底靠左 |
| `ViolationCard` | 判斷結果逐條違規/合規卡片 | 左側色條 + 標籤 + 內文 |
| `OpenSourceAiButtons` | 開源版「複製提示詞→貼到 ChatGPT/Gemini」引導卡 | indigo/purple 漸層底，三步驟按鈕 |
| `LoadingSkeleton` / `ErrorState` | 載入中／錯誤狀態 | 待重新設計（現況陽春） |

## 7. 現況美學痛點（客觀觀察，作為改善依據）

1. 大量 emoji 當圖示，尺寸與視覺風格不統一，正式場合（例如結果頁的金額試算）顯得不夠專業可信
2. 完全沒有自訂字體，繁體中文用系統 Arial 顯示，缺乏排版質感，也沒有字重層級可以區分資訊優先度
3. 色彩是 Tailwind 預設值直接套用，沒有微調過飽和度/明度，整體偏「範本感」、「一看就是用 Tailwind 快速刻出來的」
4. 卡片視覺層級單一（幾乎都是 `white + border + shadow-sm`），在資訊密度高的頁面（如詳細分析頁）容易顯得像制式表單堆疊，缺乏視覺呼吸感
5. 尚未支援 dark mode
6. 尚無品牌識別元素（沒有 logo，只有 `⚖️` emoji 當代表符號，沒有其他視覺記憶點）

## 9. 不要做的事

- 不要改變頁面的資訊架構、表單流程、判斷邏輯的呈現順序
- 不要拿掉或弱化 `DisclaimerBanner` 的警語內容（法遵需求，文字必須完整保留）
- 不要讓「深藍＋金色」變成生硬冰冷的企業風——選定方向明確是「親切溫暖」優先於「正式威嚴」，深藍金色只是配色選擇，不是要做成傳統法律事務所官網那種距離感
- 不要引入需要後端配合才能運作的新功能，這次只談前端視覺
- 不要移除雙模式架構（`opensource` / `private`）相關的 UI（`OpenSourceAiButtons` 的信任聲明文案要保留，只是可以重新設計視覺呈現）
